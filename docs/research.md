# Open Hunt Map research

Checked 2026-10-22 using live public sources. **Recommendation:** build the MIT PWA around durable local writes, downloadable map packs, and explicit nearby transfer with receipt acknowledgments. A saved basemap does not deliver a newly dropped pin to another phone: that requires a working transport between the devices. Full nationwide owner-data parity remains a separate funding/licensing problem.

“Verified” below means supported by the linked public documentation, not tested on devices. Recommendations are proposed designs. **Unverified** means evidence was insufficient; it is not permission to redistribute. The application's MIT license must remain distinct from dataset, imagery, service, and dependency terms.

## 3. Private parcels and owner names

There is no verified free, uniformly licensed nationwide owner-name layer in this research. Commercial aggregation is the practical nationwide route, exemplified by Regrid's paid nationwide coverage; free viewing is not equivalent to redistributable app/offline rights. [Regrid API](https://regrid.com/api), [paid nationwide access](https://support.regrid.com/docs/mcp-server). “Mostly commercial” describes the nationwide product market, not every underlying county record.

**Verified examples, not an exhaustive state list:** these state programs distribute statewide parcel data with owner information. “Statewide” means the program's aggregation, not guaranteed current owner names on every parcel. Free access and an explicit redistribution license are separate checks.

|---|---|---|

[MassGIS parcels](https://www.mass.gov/info-details/massgis-data-property-tax-parcels) | Specific redistribution license **unverified**; assessor data and municipal vintages vary. |

## 4. Offline-first and nearby sync

### Local storage and replication

| Option | Findings and proposed use |
|---|---|
| IndexedDB + service worker | IndexedDB for durable structured records/outbox; service worker caches the app shell. Workbox simplifies routing/caching, not peer delivery. Browser storage can be evicted and quotas differ; request persistence, handle quota failures, provide export. [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API), [Workbox](https://developer.chrome.com/docs/workbox/), [quota/eviction](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) |
| Map packs | Precompute bounded PMTiles extracts and store complete packs locally; use a local PMTiles source/adapter. Include style, glyphs, sprites, ownership/units, elevation, attribution and version manifest. Extraction is supported by the [PMTiles CLI](https://docs.protomaps.com/pmtiles/cli); pack completeness and browser-local range access remain implementation work. |
| Yjs | CRDT shared types; transport-independent updates can be persisted and delivered later. MIT. Good for concurrently edited group notes/collections; still needs a provider/transport and access control. [Project](https://github.com/yjs/yjs), [license](https://github.com/yjs/yjs/blob/main/LICENSE) |
| Automerge | Local-first JSON-like CRDT with merge/sync support; MIT. Good for document histories/conflicting edits; account for storage/history and WASM integration. [Project](https://github.com/automerge/automerge), [license](https://github.com/automerge/automerge/blob/main/LICENSE) |
| Per-item LWW | **Recommendation for first pin MVP:** globally unique item/operation IDs; HLC plus actor-ID deterministic tie-break; tombstones and idempotent operation exchange. Append track points/blood observations rather than replacing entire tracks. Smaller protocol, but concurrent updates can overwrite intent; retain conflict history. HLC is ordering metadata, not trusted wall-clock time or a causal-conflict solution. |

**Proposed reliability contract:** write the pin and outbox operation atomically before showing it as saved. Exchange missing operations over any transport; acknowledge only after receiver persistence. Preserve IDs/tombstones across QR, files, WebRTC and eventual server sync. UI states should distinguish **Saved on this phone**, **Pending**, and **Received by Dad**—a cloud upload acknowledgment cannot establish the last state. Encrypt/authenticate group transfers and confirm pairing; CRDT convergence alone provides neither privacy nor trustworthy membership.

### Transport feasibility

| Transport | What is verified; recommendation / limits |
|---|---|
| Web Bluetooth | Available in Chrome/Chromium on Android and supported desktop platforms, **not Android-only**; iOS Safari does not support it. Web API connects as central to remote GATT peripherals; no standard browser GATT-server/peripheral advertising path for browser-phone-to-browser-phone sync. HTTPS and user permission required. [Chrome platform/central-role docs](https://developer.chrome.com/docs/capabilities/bluetooth), [API/compatibility](https://developer.mozilla.org/en-US/docs/Web/API/Web_Bluetooth_API). Use for hardware radios, not the base cross-platform phone transport. |
| WebRTC over local Wi-Fi/hotspot | Data channels can carry updates peer-to-peer, but offer/answer and ICE candidates still need signaling. **Proposed offline flow:** both load the cached PWA; create data channel, wait for ICE gathering, exchange compressed SDP offer and answer via QR (multi-frame if needed), then sync. [Signaling](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Signaling_and_video_calling), [connectivity](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API/Connectivity). Internet signaling/STUN/TURN must not be assumed offline. |
| mDNS candidates | Browser privacy can replace host IP candidates with `.local` mDNS names; these are address resolution, not peer discovery or SDP signaling. [IETF explanation](https://datatracker.ietf.org/meeting/103/materials/slides-103-rtcweb-mdns-ice-candidates-00). Hotspot isolation, multicast filtering and browser candidate policy can prevent a connection. Cross-platform no-internet hotspot reliability is **unverified until device-tested**. |
| QR pin transfer | No shared network needed. Version 40-L maximum is **2,953 binary bytes** (~2.9 KB decimal); stronger error correction reduces capacity. [DENSO capacity table](https://www.qrcode.com/en/about/versionPage/versionPage31_40.html). Fit compact coordinates, ID, timestamp and short note; encoding/authentication consume capacity. For tracks/photos use numbered multi-QR or animated chunks with checksums, deduplication and completion acknowledgment; proposed protocol, not built-in QR capability. |
| Files and Web Share | Export/import GPX, GeoJSON and KML plus a native sync bundle retaining IDs/version/tombstones. Web Share can invoke OS sharing for supported files; test `canShare`, require user activation, retain download/file-picker fallback. OS target availability determines offline delivery. [Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Share_API), [GeoJSON standard](https://www.rfc-editor.org/rfc/rfc7946), [GPX specification](https://www.topografix.com/GPX/1/1/), [KML standard](https://www.ogc.org/standard/kml/). Ordinary interchange formats may lose app-specific conflict metadata. |
| Meshtastic / LoRa | Requires external radios; LoRa mesh carries small messages, not map packs. [Official introduction](https://meshtastic.org/docs/introduction/). Current official web monorepo lists `@meshtastic/sdk`, HTTP, Web Bluetooth and Web Serial transports, plus hosted web client. [Packages](https://github.com/meshtastic/web/blob/main/README.md). Verify the license of each pinned package before MIT-app integration—package-level license compatibility is **unverified** here. Browser BLE/serial support remains platform-limited; use native adapters later for iOS. Prototype compact pin deltas with acknowledgments/retry and conservative airtime; delivery is not guaranteed. |
| Garmin inReach / Explore | Garmin explicitly offers **inReach Portal Connect for Professional customers**. IPC Inbound documentation exists; API terms grant limited, revocable, non-transferable/non-sublicensable use with end-user consent. [Developer listing](https://developer.garmin.com/), [IPC documentation](https://developer.garmin.com/inReach/IPC_Inbound.pdf), [terms](https://developer.garmin.com/inreach-portal/download/). This is a proprietary portal integration, not verified open consumer Bluetooth satellite access. Consumer Explore API eligibility, direct native device protocol and general offline P2P use are **unverified**. Native wrapping alone does not grant those rights; investigate as a later paid/hardware integration. |

**Required prototype checks:** two physical phones with cellular disabled; Android↔Android, iPhone↔iPhone and Android↔iPhone. Kill/reopen after pin creation; exhaust quota; duplicate/reorder operations; edit/delete on both peers; disconnect mid-transfer; test hotspot owner/client roles. Reconcile through a later internet connection without duplicate pins or resurrected deletions. Mobile background tracking/sync reliability must also be measured before promising native parity.

## 5. “And more” product opportunities

Proposed features; these are not claims that onX lacks them:

- **Blood-trail mode:** one-tap blood/sign observations, timestamped photos, last-known sign, backtracking and separate searcher tracks. Keep observations append-only; show which partner has received each update.
- **Offline group sync:** QR for one pin immediately; file bundles for a hunt; local Wi-Fi sync when available. Preflight with an actual shared test pin before leaving service.
- **Wind-scent cone:** local visualization driven by cached wind, with forecast age and uncertainty. Treat it as an estimate, not a precise scent boundary.
- **Open layer packs:** dated public land, legal-access, units, trails, elevation and eligible imagery, with source and license carried into every downloaded pack.
- **Interoperability and ownership:** GPX/GeoJSON/KML import/export, full-fidelity backups, optional self-hosted sync and no account requirement for local recording.
- **Offline readiness:** verify usable map/DEM coverage and available storage, then run a no-network launch. A completed download indicator should mean the selected area actually renders offline.
- **Field journals and trail-camera import:** consented photos and sightings with an auditable distinction between observations and inferred activity. Avoid promising a free equivalent to proprietary vendor integrations or movement forecasts.

**Suggested delivery order:** local pins/tracks + QR/file exchange → verified regional map packs → acknowledged group replication → tested hotspot/WebRTC → state-by-state parcel adapters → radios/native background capabilities. That directly tests the deer-tracking failure before expanding the parity checklist.
